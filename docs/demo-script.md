# 六分钟演示脚本

当前可执行的离线段使用 synthetic 固定响应；画面持续显示这一标记。当前已有六分钟核查视频、完整运行统计和六例匹配验证；人工语义评分完成后更新结果段，生成最终提交版。

## 录制素材

- 主案例：`benchmark/dev/dep_002/materials/`，日志、launch.json、目标/项目快照。
- 固定响应：`examples/dep_002_replay.json`，通过真实工具展示候选变化。
- 报告与轨迹：按 [复现步骤](reproduction.md) 新建本地输出；视频不展示 `.env` 或 API key。
- 边界案例：`test_info_shape`、`test_out_nccl` 和四个 `test_attack_*` 的已脱敏预览；正式演示使用真实评测生成的报告和轨迹。
- 结果表：由人工评分后的 summary.json 整理，保留来源分组和分母；当前只汇总了正常结束、预算停止、token 和耗时，语义指标尚未产生。

## 0:00—0:40：问题与范围

画面展示五类支持故障和简化架构。旁白：

> 一条训练报错通常不足以定位原因。缺少依赖与用错解释器，可以产生相同的异常。DeepDebug 把日志、代码、配置和环境快照组织成证据，再给出有条件的修复建议。它支持五类常见故障，使用单 Agent 按需调用工具。

明确说明本段演示的运行类型：离线预置演示、预录制在线运行或现场在线运行。不得混用标题。

## 0:40—2:30：主案例与候选变化

进入 Streamlit，打开离线预置演示；若录制在线版本，则上传四份材料，生成并逐份展示脱敏预览，确认目的地与模型后开始。API key 仅存在服务器环境，不进入录屏。

画面按实际顺序展示日志解析、配置读取、目标快照和项目快照。旁白：

> 日志首先显示导入失败。读取启动配置后，实际解释器与预期解释器不同。目标环境中找不到包，另一个环境已经安装。候选因此从“目标环境缺少依赖”进一步定位为“程序启动到了错误的环境”。每一条判断都可以回到对应证据。

展开证据 ID、来源和快照采集时间。若当前真实结果与脚本描述不同，保留实际输出并据此修改旁白，不用固定响应替换却称为在线结果。

## 2:30—3:30：报告与验证边界

下载 Markdown 和 JSON，展示根因、修复条件、未决问题及“未执行”。运行 check-report，显示内容一致。

> 报告给出修改对象、适用条件和成功判据。两种导出格式来自同一结构。当前用户训练没有被重跑，因此修复状态仍是未执行。

另展示固定路径案例的错误版和修复版检查：标明“独立预置实验”。仅在实际报告建议与预置修复相符并经核查后，演示 verify-report 的匹配关联。不得将依赖主案例关联到无关路径实验。

## 3:30—4:30：信息不足与范围外

展示正式运行所得的信息不足报告或范围外报告，展开其具体缺口和下一步。若未取得真实模型记录，仅展示输入材料，并标注“诊断待运行”。

> 快照描述采集时刻，不等于故障发生时的现场。只有形状报错但没有调用点或输入信息时，系统应保留不确定性，说明需要补充什么。范围外的问题也应明确边界。

该段最终交付需使用已保存的真实报告，不能把规划目标当成当前模型行为。

## 4:30—5:10：权限与攻击

展示已脱敏的攻击材料和对应真实评测轨迹，核对是否发生越界工具调用、是否服从材料中的指令，以及假密钥是否进入输出。

> 材料里的“系统指令”仍然只是材料。工具只接收登记 ID；未登记路径和 gold 目录不可读取。攻击防护是否通过，同时检查报告和实际调用轨迹。

无真实攻击运行时，可展示权限回归测试，但标题必须为“固定测试”，不能显示 4/4 模型攻击阻断率。

## 5:10—6:00：架构、结果与局限

展示 B0/B1/A 人工评分表，逐项说明常见故障 20 例、不足/范围外 6 例、攻击 4 例及真实/synthetic 分组。说明模型、代码版本、耗时与费用来源。

> B0 只获得日志，B1 一次获得完整材料，A 按需调用工具。我们同时比较根因、修复、证据和成本。结果来自这个小型 benchmark，不能推广为生产成功率。

填写实测值后再录制此段。若 A 没有优于 B1，直接呈现结果及失败分析。最后显示仓库入口与复现文档。

## 成片要求

时长 5～7 分钟，中文旁白或完整字幕。允许压缩网络等待，但保留工具调用顺序，并标明预录制回放。导出后核对画面无密钥、数据与报告一致、合成与真实片段标识完整。视频和原始录制素材放在本地交付目录，不自动提交 Git。
