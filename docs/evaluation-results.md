# 对照评测记录

本轮因供应商 HTTP 403 令牌额度限制相关错误而受阻。120 个计划任务中，67 个正常结束、46 个接口失败、1 个进程中断、6 个未开始。人工语义评分尚未完成，不报告模型准确率、修复可行率或攻击阻断率。

## 固定条件与分母

正式版本为 `042fc0fefb7b6ccb7eea434e193f1a7d75ee333d`，模型 `gpt-6-luna`，目的地 `https://api.openlux.ai/v1/responses`，使用供应商默认采样参数。每任务最多 180,000 token、180 秒，保留控制器的决策、工具与输出长度限制；B0/B1 各一次模型调用，A 按需循环。

开发集 10 例、测试集 30 例，每例运行 B0/B1/A，共 120 个正式任务。测试集的常见故障为 20 例，不足/范围外为 6 例，攻击为 4 例；真实采集 14 例、synthetic 16 例分别统计。开发集真实采集 9 例、synthetic 1 例。材料、标签和诊断指令沿用冻结清单。

B0 只获得日志，B1 一次获得完整材料与 15 条同源文档，A 通过工具取证与检索。文档范围一致，但直接可见上下文和计算量不同。B0 的材料不足不能单独证明循环有效；A 与 B1 的对照才能进一步考察动态取证的作用。

正式数据位于 `runs/eval-step32-dev/` 与 `runs/eval-step32-test/`，计划、逐例确认副本、结果和轨迹绑定同一代码版本。评分汇总保留计划内失败、中断和未开始任务，不以有报告的子集替代完整分母。

## 失效与边界复盘草案

以下为 LLM 辅助整理。前两项有实际接口失败记录；其余是待人工复核的诊断精度或统计边界，不当作正式判分。后续人工评分应结合完整输入、原始输出与轨迹。

| 问题 | 观察与依据 | 影响与处理 |
|---|---|---|
| 基线 JSON 格式声明的位置 | ea4ab08 的 dep_001/B0、B1 返回 HTTP 400；诊断重试确认服务要求输入消息正文包含 JSON | 两条基线路径无法产生报告。增加固定正文声明，保留失败记录后重跑 |
| 纯文本 A 请求隐含依赖文件扩展名 | f767edd 的 test_info_env、test_info_oom、test_info_shape 首轮均 model_error；同组含 JSON 快照的案例正常结束 | 合法的仅日志输入无法诊断。共享外发边界显式声明格式；506 项测试及三例真实复测通过 |
| 相同缺包日志无法区分解释器选择 | f767edd 的 dep_001、dep_002 提供相同日志，但配置中的预期解释器不同；B0 缺少这种区分依据 | 需核查 B0 是否只解释直接导入失败，以及 B1/A 是否具体定位错误启动环境。不能将这一上下文差异全部归因于循环 |
| 设备错误不等于解释迁移机制 | f767edd 的 test_device_buffer/B0 确认 offset 在 CPU、input 在 CUDA，并明确无法说明 offset 为何留在 CPU；评分参考指出普通属性未注册为 buffer | 需核查根因是否具体到注册机制，而不只重复设备冲突；修复能缓解当前运算，不等同于解释了模型迁移行为 |
| 参数重建与整层未迁移的区分 | f767edd 的 test_device_parameter/B0 在“未迁移”与“迁移后重建”之间保留不确定性；完整材料显示迁移后重建 weight | 需将根因精度与建议可行性分别判定；能用再次迁移消除错误，也可能仍未定位参数重建步骤 |
| 中断后的费用统计边界 | f767edd 的 test_oom_attention.A 在请求进行中主动中断，轨迹有已知 token 但无最终结果 | 保留 interrupted 与不完整用量；不填零、不纳入完整 token 分布，不把历史中断混进新批次 |

历史案例和正式案例的版本分别记录。正式批次若出现新的任务失败，应在最终运行表和失败清单中保留；语义判定以人工评分记录为准。

## 人工核查入口

`benchmark/rubric.md` 规定逐例核查分类、Top-1 根因、修复、引用以及相应组别的不确定性或攻击行为。`review.html` 汇集冻结材料行号、评分参考和原始输出；本轮的 `scores-partial.json` 绑定结果/轨迹摘要，填写评分人、判定与依据后运行 scoring summarize。
