# 当前架构与设计决策

本文按模块说明当前架构及设计理由。接口参数、返回值和约束见 [工具协议](tool-api.md)；逐步改动、验证结果和下一步任务见 [开发进度](progress.md)。产品范围与验收目标以 [项目规划](../DeepDebug_planning.md) 为准。

## 基础工程与依赖

采用 Python 3.10+、`src/deepdebug` 包布局和 uv，默认开发解释器为 Python 3.12。`pyproject.toml` 管理版本与依赖声明，`uv.lock` 锁定依赖；CLI 从安装元数据获取版本，避免重复维护版本号。

标准库 argparse 负责命令行交互，`deepdebug` 与 `python -m deepdebug` 共享 `main()`。Pydantic v2 负责数据协议和边界校验，pytest 与 Ruff 分别用于测试和静态检查。BM25 使用标准库实现；Streamlit 和模型 SDK 随对应功能引入。普通快照取证无需安装 PyTorch、GPU 驱动或配置模型密钥。独立的 `capture` 开发依赖组包含固定版本 PyTorch 2.9.1 与 NumPy，用于真实故障采集；Linux/Windows 的 torch 来自显式 CUDA 12.8 官方索引，其他包仍用默认包源。

## 当前数据流与模块职责

当前入口提供离线控制循环、宿主取证、环境采集和独立文档检索：

```text
replay      → 材料登记 → 固定日志解析 → 模型响应回放 ↔ 受限工具 → JSON 报告 / JSONL 轨迹
collect     → 材料登记 → 日志解析 → 代码/配置读取 → 快照及可选 GPU 查询
            → 可选路径检查 → 可选文档检索 → DiagnosisState JSON
snapshot    → 显式选择解释器 → 固定环境探针 → EnvironmentSnapshot JSON
search-docs → 固定语料检索 → 文档证据与工具记录 → DiagnosisState JSON
```

| 模块 | 职责 |
|---|---|
| `cli.py`、`__main__.py` | 参数、输出和退出码 |
| `replay.py`、`llm/client.py` | 离线回放、模型请求/响应契约与固定响应客户端 |
| `agent/controller.py`、`decision.py`、`trace.py` | 决策校验、循环、预算、停止报告与 JSONL 检查点 |
| `tools/registry.py` | 环境/路径 ID 绑定、白名单调度与会话缓存 |
| `collection.py` | 组织固定取证流程和独立检索 |
| `tools/session.py` | 执行宿主工具方法、登记结果并更新会话状态 |
| `tools/` 中的具体工具 | 材料读取、日志解析、环境采集与快照读取、路径检查、文档检索 |
| `agent/schemas.py`、`actions.py`、`state.py` | 数据结构、动作参数与跨记录一致性校验 |
| `agent/evidence.py` | 会话内证据编号与去重 |
| `security/paths.py` | 授权目录、受限读取与路径检查 |

CLI 只负责交互，流程组织与工具实现分别维护。工具返回事实；离线控制器接受固定模型响应中的假设与动作，执行真实工具并将观察送入下一轮请求。真实模型自动诊断待云端接入后验证。

## 材料边界与内容固定

宿主通过 POSIX 目录文件描述符读取独立授权目录中的显式材料，拒绝越界、链接和答案目录。登记后固定材料内容，工具按材料 ID 读取内存副本，避免后续文件编辑使证据内容和行号漂移。该读取方式依赖 POSIX，Windows 取证暂不支持。

路径检查只观察宿主登记引用的存在性和类型，不遍历目录或读取目标内容。材料读取与路径检查共用授权边界，前者使用登记时内容，后者保持目录句柄直到本次检查结束。

日志、代码、配置和检索文档均作为不可信数据处理。材料当前保留 `redaction_status=pending`，输出仅供本地检查；自动脱敏与发送模型前的范围确认尚未实现。

## 协议、状态与证据

协议按职责分为 `schemas.py`（材料、证据、快照与报告）、`actions.py`（动作及工具参数）、`state.py`（会话与跨记录一致性）。协议负责结构校验，文件权限由工具层执行，模型决策由 `Decision` 校验，离线循环中的会话预算停止由控制器负责。

`CollectionSession` 将成功和失败都写入工具历史，并在每次更新边界重建、校验完整状态。工具结果和材料片段有大小限制，截取保留原始位置及截断标记。`EvidenceRegistry` 按来源、位置、内容、时间和截断标记去重；重复观察复用证据编号，调用记录仍独立保存。

证据保留来源中的采集时间，工具耗时单独记录。快照字段证据使用原始 JSON 值，文档证据携带 URL、版本、整理时间及摘要位置。报告协议检查引用和状态一致性，证据对结论的语义支持仍需诊断与评测环节判断。

## 环境采集与来源区分

实时采集放在显式 `snapshot` 命令，`collect` 导入用户提供的快照。这样用户可以选择实际训练解释器，而取证进程无需与目标环境运行在同一机器。第一份快照绑定目标环境；读取失败时保持目标未知，对照快照不替换目标。

`tools/capture.py` 构造固定探针，`process.py` 执行超时、输出限制和进程回收。Python 探针使用隔离参数和项目目录外的临时工作目录，减少同名模块影响；包元数据查询不导入目标包。可选 PyTorch/CUDA 与 GPU 探针分别记录状态和采样时间，部分采集失败仍保留有效 Python 身份。

GPU 查询保留快照采样时间；路径检查标记为运行命令主机的 `local/collector`。来源与时间用于区分目标快照、本机观察和故障发生时的环境，不能由一次采集推定历史训练状态。固定探针的执行边界不构成通用进程沙箱。

## 本地文档检索

语料唯一副本为 `src/deepdebug/knowledge/documents.json`，随包发布；[语料说明](../knowledge/README.md) 维护来源清单、评分公式和分词规则。运行时固定目录和文件名，查询不能指定读取路径或下载 URL，避免将仓库和 benchmark 标签纳入检索。会话首次查询后固定语料内容，使证据在会话内保持一致。

文档读取复用 POSIX 文件边界，固定包根目录允许隐藏组件以支持 `.venv` 安装；链接和 gold 仍被拒绝，用户材料目录维持原规则。通过 uv 安装 wheel 时使用 `--link-mode copy`，避免安装器创建的硬链接被拒绝。

采用 BM25 衡量词的区分力、词频饱和与文档长度，标准库实现适用于当前小规模静态语料。标题、关键词和摘要合并索引，类别只过滤候选，不改变完整语料统计。分词保留异常名、下划线标识符、完整 API 与后缀别名，以支持完整报错和 API 简称查询；中文采用相邻双字片段。

`tools/docs_search.py` 负责语料校验和排序，`CollectionSession.search_docs` 负责工具记录与证据登记。文档提供带版本的一般规则；排序分数和版本标注不自动承担实例根因或版本兼容性判断。

## 开发案例与标签隔离

两个依赖开发案例使用同一日志和脚本，通过目标环境快照及启动配置区分缺包与错误解释器。它们属于同一案例族，均留在开发集，避免相似案例跨集合造成评测泄漏。

六个已采集开发案例覆盖五类故障，均保留输入与人工参考答案分离。固定故障采集脚本使用显式选择的解释器，在临时目录写入开发者维护的程序；采集器与 Agent 工具隔离。只有匹配预期异常的真实非零退出才落盘为案例，环境不足与超时等结果写入采集汇总。路径种子另存故障环境中的文件布局；配额 OOM 通过进程显存上限与固定 64 MiB 申请触发，不能据此推断整卡显存耗尽。

`tools/process.py` 的内部返回保留完整非零退出输出与退出码，供采集器识别真实失败；环境探针仍将非零退出映射为错误，失败输出不会作为成功环境证据。

输入材料位于 `benchmark/dev/*/materials/`，人工参考状态与报告位于 `benchmark/gold/dev/`，仅供开发与评测使用。案例 Python 文件作为原始输入由 Ruff 排除，防止格式化改变证据行号；工具读取和文档检索均隔离 gold。

## 单 Agent 控制器与模型接口

`Controller` 只接受新登记会话，先固定解析日志，再向 `ModelClient.decide` 提交状态副本、可用环境/路径 ID、决策 Schema、剩余时间与 token 额度。`Decision` 只包含观察摘要、最多三个假设、一个动作及结束结论；工具结果、证据内容、验证执行状态和最终报告中的环境均由宿主维护。每次决策、调度、轨迹写入和报告输出重校验完整状态，引用无效的决策不会部分提交。

`ToolDispatcher` 使用显式分支调用现有工具，不接受方法名或命令执行。环境 ID 由已登记快照解析，重复 ID 不提供绑定；比较快照不会替换第一份目标快照，GPU 查询也不更换目标。探针选择只影响返回字段和证据；`run_builtin_check` 返回 `unavailable`。缓存按工具名和完整参数保存，包括失败结果；命中复用原调用 ID，在轨迹中记录本次动作，不重复增加工具计数。路径缓存表示首次检查时刻。

预算在每轮决策前、模型返回后及工具边界检查。无效决策可修正一次；模型接口的 timeout/unavailable 在会话内可重试一次，两者均计入决策次数。连续两轮没有新证据或假设变化则停止；仅观察摘要变化不算进展。模型接口错误、无效动作、预算耗尽和缺信息均保留已有证据，并由宿主生成 JSON 停止报告。同步本地工具在返回后检查总时限；单次工具抢占和真实网络超时留给后续执行器/适配器落实。

当前唯一客户端是 `ReplayModelClient`，响应由人工 JSON 文件提供，token 为文件声明的模拟用量。控制器拒绝 remote 客户端，材料尚未经脱敏，状态和轨迹仅供本地使用。`examples/dep_002_replay.json` 演示配置与快照使候选原因从缺包细化到解释器不一致；固定答案只用于演示与控制器回归，不用于衡量模型诊断能力。

## 报告与轨迹

控制器从结论字段与宿主事实组装 `DiagnosisReport`；模型不能自行提供证据内容、工具历史或执行验证记录。修复验证固定为“未执行”，正常结束校验支持证据，异常停止保留候选原因和未决项。报告嵌入最终状态 JSON，当前无需额外报告模型调用，报告 token 预留未消费。

`JsonlTrace` 通过调用方显式提供的文本流逐事件写入并 flush，包含序号、记录时间、会话 ID、事件详情和完整状态。缓存动作指向原工具调用 ID。CLI 的 `--trace` 只新建文件；中断时已写入检查点可读，续跑和自动清理尚未实现。轨迹包含原始证据和路径，受与材料相同的隐私限制。

Markdown 渲染、Streamlit、脱敏确认、云端适配、内置修复验证及真实模型五类端到端验收仍待实现。后续任务与验收缺口统一维护在 [开发进度](progress.md)。
