# 当前架构与设计决策

本文按模块说明当前架构及设计理由。接口参数、返回值和约束见 [工具协议](tool-api.md)；逐步改动、验证结果和下一步任务见 [开发进度](progress.md)。产品范围与验收目标以 [项目规划](../DeepDebug_planning.md) 为准。

## 基础工程与依赖

采用 Python 3.10+、`src/deepdebug` 包布局和 uv，默认开发解释器为 Python 3.12。`pyproject.toml` 管理版本与依赖声明，`uv.lock` 锁定依赖；CLI 从安装元数据获取版本，避免重复维护版本号。

标准库 argparse 负责命令行交互，`deepdebug` 与 `python -m deepdebug` 共享 `main()`。Pydantic v2 负责数据协议和边界校验，pytest 与 Ruff 分别用于测试和静态检查。BM25 使用标准库实现；HTTPX 负责模型 HTTP 访问，Streamlit 待引入。普通快照取证无需安装 PyTorch、GPU 驱动或配置模型密钥。独立的 `capture` 开发依赖组包含固定版本 PyTorch 2.9.1 与 NumPy，用于真实故障采集；Linux/Windows 的 torch 来自显式 CUDA 12.8 官方索引，其他包仍用默认包源。

## 当前数据流与模块职责

当前入口提供材料预览/确认、云端诊断、离线控制循环、宿主取证、环境采集和独立文档检索：

```text
preview → 显式材料登记 → 常见规则脱敏 → 含完整文本和摘要的预览
confirm → 预览与摘要校验 → 固定确认副本 → replay --reviewed
diagnose → 固定确认副本 + 外发目的地/模型/摘要授权 → 请求边界 → 云端模型 ↔ 受限工具
replay      → 材料登记 → 固定日志解析 → 模型响应回放 ↔ 受限工具 → JSON 报告 / JSONL 轨迹
collect     → 材料登记 → 日志解析 → 代码/配置读取 → 快照及可选 GPU 查询
            → 可选路径检查 → 可选文档检索 → DiagnosisState JSON
snapshot    → 显式选择解释器 → 固定环境探针 → EnvironmentSnapshot JSON
search-docs → 固定语料检索 → 文档证据与工具记录 → DiagnosisState JSON
```

| 模块 | 职责 |
|---|---|
| `cli.py`、`__main__.py` | 参数、输出和退出码 |
| `replay.py`、`llm/client.py` | 离线回放、模型请求/响应契约与固定响应客户端 |
| `diagnosis.py`、`llm/openai.py`、`security/outbound.py` | 已授权云端会话、Responses HTTP 适配、逐轮范围校验与请求脱敏 |
| `agent/controller.py`、`decision.py`、`trace.py` | 决策校验、循环、预算、停止报告与 JSONL 检查点 |
| `tools/registry.py` | 环境/路径 ID 绑定、白名单调度与会话缓存 |
| `collection.py` | 组织固定取证流程和独立检索 |
| `tools/session.py` | 执行宿主工具方法、登记结果并更新会话状态 |
| `tools/` 中的具体工具 | 材料读取、日志解析、环境采集与快照读取、路径检查、文档检索 |
| `agent/schemas.py`、`actions.py`、`state.py` | 数据结构、动作参数与跨记录一致性校验 |
| `agent/evidence.py` | 会话内证据编号与去重 |
| `security/paths.py` | 授权目录、受限读取与路径检查 |
| `security/redaction.py`、`review.py` | 跨材料一致替换、预览协议、摘要确认及固定副本加载 |
| `security/destination.py` | API 基础地址解析、Responses 目的地拼接和规范化校验 |

CLI 只负责交互，流程组织与工具实现分别维护。工具返回事实；控制器接受模型响应中的假设与动作，执行真实工具并将观察送入下一轮请求。离线响应和 HTTP 模拟已用于测试，真实模型自动诊断待验证。

## 材料边界与内容固定

宿主通过 POSIX 目录文件描述符读取独立授权目录中的显式材料，拒绝越界、链接和答案目录。登记后固定材料内容，工具按材料 ID 读取内存副本，避免后续文件编辑使证据内容和行号漂移。该读取方式依赖 POSIX，Windows 取证暂不支持。

路径检查只观察宿主登记引用的存在性和类型，不遍历目录或读取目标内容。材料读取与路径检查共用授权边界，前者使用登记时内容，后者保持目录句柄直到本次检查结束。

日志、代码、配置和检索文档均作为不可信数据处理。直接 `collect/replay --root` 保留 `redaction_status=pending`。`preview` 先登记全部显式输入，再统一发现敏感值并替换，保证重复凭据和用户目录前缀在不同材料中使用相同别名。显示名改为材料 ID 加原扩展名，原目录及替换映射不写入预览。

`security/redaction.py` 用有限规则识别常见凭据、私钥与用户目录前缀。文本替换保留物理行数；有效 JSON 在字符串解码后替换并重新转义，保留结构、排版和快照采集时间，数字凭据字段替换为字符串占位符。自动规则不能覆盖全部私有内容，用户须核查完整预览；遗漏内容通过修改输入副本后重新预览处理。

`MaterialReview` 保存有序脱敏材料及其 SHA-256。确认绑定内容、类型、顺序、登记时间和规则版本；在确认、保存、加载和回放边界重校验。确认文件保存完整副本，后续运行不再读取原始文件。文件以 0600 权限独占新建；外层 JSON 读取上限 128 MiB，解码后每份仍限 2 MiB、总计 10 份，以容纳 JSON 转义膨胀。

`replay --reviewed` 将确认副本装入独立材料登记表，状态材料标记为 reviewed，并记录 `material_review_sha256`。工具、证据、模型请求中的材料和轨迹都从该表生成；原文件修改、删除不改变当前运行。证据位置指向脱敏副本。已确认回放不接受追加原始材料或本机路径，因为这些观察尚未进入确认范围。

摘要用于本地内容一致性检查，不承担签名或用户身份认证。`confirm` 命令表示已核查副本，`diagnose --send-to` 表示同意外发；两者显示材料清单，诊断还显示目的地和模型。程序自动校验副本摘要，并将它与目的地、模型共同写入 `CloudConsent`，随状态和轨迹保存。本地单用户可编辑文件，确认记录不作为跨用户的安全凭据。

`OutboundBoundary` 绑定确认副本和当前 `ToolDispatcher`，每轮比较登记文本、元数据、会话状态、证据登记表和可用环境，拒绝额外材料及本机路径。云端客户端只能配合这个 dispatcher 使用。发送内容包含目标快照的环境标识、解释器和采集时间，以及当前工具已观察到的片段和判断，完整源文件不附加到请求；对序列化请求中的文本再次脱敏，API key 作为额外已知敏感值屏蔽。预览占位符在重复脱敏时保持稳定；模型返回文本在进入状态与轨迹前执行同一规则。原始证据仍指向确认副本，再次脱敏只改变外发副本。

## 协议、状态与证据

协议按职责分为 `schemas.py`（材料、证据、快照与报告）、`actions.py`（动作及工具参数）、`state.py`（会话与跨记录一致性）。协议负责结构校验，文件权限由工具层执行，模型决策由 `Decision` 校验，离线循环中的会话预算停止由控制器负责。

`CollectionSession` 将成功和失败都写入工具历史，并在每次更新边界重建、校验完整状态。工具结果和材料片段有大小限制，截取保留原始位置及截断标记。`EvidenceRegistry` 按来源、位置、内容、时间和截断标记去重；重复观察复用证据编号，调用记录仍独立保存。

普通文本证据的 `collected_at` 是材料登记时间，不表示日志中的故障发生时间；快照字段证据使用快照内的采集时间，工具耗时单独记录。快照字段证据使用原始 JSON 值，文档证据携带 URL、版本、整理时间及摘要位置。报告协议检查引用和状态一致性，证据对结论的语义支持仍需诊断与评测环节判断。

## 环境采集与来源区分

实时采集放在显式 `snapshot` 命令，`collect` 导入用户提供的快照。这样用户可以选择实际训练解释器，而取证进程无需与目标环境运行在同一机器。第一份快照绑定目标环境；读取失败时保持目标未知，对照快照不替换目标。

`tools/capture.py` 构造固定探针，`process.py` 执行超时、输出限制和进程回收。Python 探针使用隔离参数和项目目录外的临时工作目录，减少同名模块影响；包元数据查询不导入目标包。可选 PyTorch/CUDA 与 GPU 探针分别记录状态和采样时间，部分采集失败仍保留有效 Python 身份。

GPU 查询保留快照采样时间；路径检查标记为运行命令主机的 `local/collector`。来源与时间用于区分目标快照、本机观察和故障发生时的环境，不能由一次采集推定历史训练状态。固定探针的执行边界不构成通用进程沙箱。

## 本地文档检索

语料唯一副本为 `src/deepdebug/knowledge/documents.json`，随包发布；[语料说明](../knowledge/README.md) 维护来源清单、评分公式和分词规则。运行时固定目录和文件名，查询不能指定读取路径或下载 URL，避免将仓库和 benchmark 标签纳入检索。会话首次查询后固定语料内容，使证据在会话内保持一致。

文档读取复用 POSIX 文件边界，固定包根目录允许隐藏组件以支持 `.venv` 安装；链接和 gold 仍被拒绝，用户材料目录维持原规则。通过 uv 安装 wheel 时使用 `--link-mode copy`，避免安装器创建的硬链接被拒绝。

采用 BM25 衡量词的区分力、词频饱和与文档长度，标准库实现适用于当前小规模静态语料。标题、关键词和摘要合并索引，类别只过滤候选，不改变完整语料统计。分词保留异常名、下划线标识符、完整 API 与后缀别名，以支持完整报错和 API 简称查询；中文采用相邻双字片段。

`tools/docs_search.py` 负责语料校验和排序，`CollectionSession.search_docs` 负责工具记录与证据登记。文档提供带版本的一般规则；排序分数和版本标注不自动承担实例根因或版本兼容性判断。

## 开发案例与标签隔离

两个依赖开发案例使用同一日志和脚本，通过目标环境快照及启动配置区分缺包与错误解释器。它们属于同一案例族，均留在开发集，避免相似案例跨集合造成评测泄漏。

六个已采集开发案例覆盖五类故障，均保留输入与人工参考答案分离。固定故障采集脚本使用显式选择的解释器，在临时目录写入开发者维护的程序；采集器与 Agent 工具隔离。只有匹配预期异常的真实非零退出才落盘为案例，环境不足与超时等结果写入采集汇总。路径种子另存故障环境中的文件布局；配额 OOM 通过进程显存上限与固定 64 MiB 申请触发，不能据此推断整卡显存耗尽。

`tools/process.py` 的内部返回保留完整非零退出输出与退出码，供采集器识别真实失败；环境探针仍将非零退出映射为错误，失败输出不会作为成功环境证据。

输入材料位于 `benchmark/dev/*/materials/`，人工参考状态与报告位于 `benchmark/gold/dev/`，仅供开发与评测使用。案例 Python 文件作为原始输入由 Ruff 排除，防止格式化改变证据行号；工具读取和文档检索均隔离 gold。

## 单 Agent 控制器与模型接口

`agent/decision.py` 的模型指令要求区分直接表现与根因，选择配置、日志及环境证据来区分假设，并在结束前处理可由登记材料回答的关键疑问。依赖问题需区分缺包与环境选错。 支持证据需指向当前实例，已排除或无实例支持的候选可删除；结束时检查摘要、置信度与支持/反对证据一致。每条主、备修复都检查对已读代码和配置其他使用点的影响，条件或验证不同的方案分开列出。时间判断依据材料正文，不将普通材料登记时间视为故障时间；日志解析已截断且关键事实缺失时，使用行号和总行数指导补读。该规则引导模型取证，不是宿主对报告语义的强制校验；在线效果记录见 [开发进度](progress.md)。

`Controller` 只接受新登记会话，先固定解析日志，再向 `ModelClient.decide` 提交状态副本、可用环境/路径 ID、决策 Schema、剩余时间与 token 额度。`Decision` 只包含观察摘要、最多三个假设、一个动作及结束结论；工具结果、证据内容、验证执行状态和最终报告中的环境均由宿主维护。每次决策、调度、轨迹写入和报告输出重校验完整状态，引用无效的决策不会部分提交。 `need_info` 可携带可选结论；在接纳判断前校验结论中的修复及证据引用，报告保留摘要、分类和条件性建议，并按顺序合并、去重动作问题与结论未决问题。没有结论的旧响应仍可使用。

`ToolDispatcher` 使用显式分支调用现有工具，不接受方法名或命令执行。环境 ID 由已登记快照解析，重复 ID 不提供绑定；初始化时将首份有效且 ID 唯一的快照身份复制到完整校验后的状态，使目标环境不依赖模型选择哪个工具。该步骤只绑定身份，不新增证据、工具记录或预算用量；包版本和探针数据仍由工具按需取得。比较快照不会替换第一份目标快照，GPU 查询也不更换目标。探针选择只影响返回字段和证据；`run_builtin_check` 返回 `unavailable`。缓存按工具名和完整参数保存，包括失败结果；命中复用原调用 ID，在轨迹中记录本次动作，不重复增加工具计数。路径缓存表示首次检查时刻。

预算在每轮决策前、模型返回后及工具边界检查。无效决策可修正一次；模型接口的 timeout/unavailable 在会话内可重试一次，两者均计入决策次数。连续两轮没有新证据或假设变化则停止；仅观察摘要变化不算进展。模型接口错误、无效动作、预算耗尽和缺信息均保留已有证据，并由宿主生成 JSON 停止报告。同步本地工具在返回后检查总时限；模型 HTTP 请求由异步截止时间取消等待。

`ReplayModelClient` 的响应由人工 JSON 文件提供，token 为文件声明的模拟用量。`--root` 使用原文，`--reviewed` 使用确认副本。`examples/dep_002_replay.json` 演示配置与快照使候选原因从缺包细化到解释器不一致；固定答案只用于演示与控制器回归，不用于衡量模型诊断能力。

CLI 使用 python-dotenv 加载当前工作目录的 `.env`，保留已有环境变量；不向父目录搜索配置。CLI 按 `--base-url`、`OPENAI_BASE_URL`、`https://api.openai.com/v1` 的优先级选择基础地址，保留版本/网关前缀，去掉尾斜杠后追加 `/responses`。`security/destination.py` 统一规范化 URL，支持 HTTP/HTTPS，拒绝内嵌凭据、查询参数、片段和空白；CloudConsent 在状态边界复用同一校验。启动前将最终地址与显式 `--send-to` 比较，匹配后才建立会话。客户端只使用确认记录中的地址，后续环境变量变化不改变目的地。

`OpenAIResponsesClient` 只从 `OPENAI_API_KEY` 读取凭据，关闭代理环境变量、重定向和隐式重试。HTTP 用于显式选择的服务，会明文传输凭据与材料。自定义地址复用 Responses 协议，服务须支持现有请求字段和返回结构；Chat Completions 适配尚未实现。采用 Responses JSON mode，将现有完整决策 Schema 放入用户数据，并由 Pydantic 验证结果；避免把包含判别联合的本地协议改成供应商的 Schema 子集。`store=false` 控制响应存储选项，不代表供应商零保留。接口依据见 [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create) 与 [JSON mode 说明](https://developers.openai.com/api/docs/guides/structured-outputs)。

HTTPX 异步流逐块读取，响应解码后最多 1 MiB；`asyncio.wait_for` 覆盖连接、读取与关闭，以控制器剩余时间减去请求准备时间为限。当前同步客户端入口使用 `asyncio.run`，供 CLI 调用。输入以 UTF-8 字节数加固定余量保守预留，输出上限最多 4,096 token；额度不足直接停止。API 用量字段必须有效，拒答、截断和非决策输出仍保留已返回用量。缺失用量或网络异常记录 `usage_complete=false`，已知总量不能充当完整账单。取消本机等待无法证明服务端停止生成或计费；这些传输分支已用 HTTP 模拟验证，实际供应商行为待实跑。

## 报告与轨迹

控制器从结论字段与宿主事实组装 `DiagnosisReport`；模型不能自行提供证据内容、工具历史或执行验证记录。修复验证固定为“未执行”，正常结束校验支持证据，异常停止保留候选原因和未决项。报告嵌入最终状态 JSON，当前无需额外报告模型调用，报告 token 预留未消费。

`JsonlTrace` 通过调用方显式提供的文本流逐事件写入并 flush，包含序号、记录时间、会话 ID、事件详情和完整状态。缓存动作指向原工具调用 ID。CLI 的 `--trace` 只新建文件；中断时已写入检查点可读，续跑和自动清理尚未实现。轨迹包含原始证据和路径，受与材料相同的隐私限制。

`reporting/render.py` 从重新校验的完整状态提取报告，确定性输出 JSON 和 Markdown。Markdown 按报告章节展示全部字段，自由文本使用长度超过内容反引号序列的代码围栏，工具数据保留为 JSON 字面量。导出不调用模型、不改变执行状态；独立 `check-report` 比较 JSON 重渲染结果和 Markdown，人工改动格式也视为不一致。CLI 输出文件仅新建且权限为 0600。

Streamlit 与内置修复验证待完成。后续任务与验收缺口统一维护在 [开发进度](progress.md)。
